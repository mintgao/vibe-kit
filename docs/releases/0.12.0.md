# Vibe Kit 0.12.0 — intended Pre-release

This version targets a non-draft GitHub Pre-release. Source implementation and
offline profile validation alone do not establish publication,
public verification, issue closure, project upgrade or active host rules.

## Changes

- Onboarding schema 1 accepts only exact integer `1`; booleans, floats and unknown
  versions fail without rewriting project state. Valid existing state needs no migration.
- Applicable shared-helper handoffs connect the configured check and actual default
  entry to the loaded helper origin/arguments and focused Python discovery/Node
  package-script execution. The managed example ships with both workflows;
  historical callers and independent QA's complete-run ownership remain intact.
- `inspect-run <target> --run-id <id> [--final-receipt <path>]` reads existing
  historical verification evidence without starting checks or changing files.
  Metadata, selected receipt, binding, coverage, one artifact set and historical
  receipt/run verdicts remain distinct. Explicit receipt selection never falls back
  and a safe copy does not attest the unselected original receipt slot.
- Exact publication schema 7 binds only v0.12.0 to six ordered operations, five
  assets and seventeen public smokes. It uses the actual PR-merged source for its
  release gate. Publication acceptance covers AC-1–AC-10; separate closeout schema 5
  permits only ordered #20/#22/#23 after verified public acceptance. Project
  upgrade and activation remain later independent stages.

## Compatibility and limits

Inspection caps receipts at 1 MiB, each streamed log at 64 MiB, selected logs at
four and output at 32 KiB. Applicability remains `unproven`, origin `not-attested`
and liveness `not-assessed`. Interrupted or partial evidence cannot become a
current-candidate pass. Consistent copied evidence cannot prove provenance.
Known-pattern sanitization cannot detect every secret or prove descendant cancellation.

Producer defaults, execution schema 1 and verify result schema 2 are unchanged.
The CLI remains offline-capable, Python 3.9+ and standard-library-only. Other
protocols and historical publication 1–6 / closeout 1–4 retain their exact meaning;
schema 6 remains exclusively v0.11.0. #21/#26 are assessment-only and #24/#25
remain deferred. Static scenarios do not establish live-model compliance,
publisher signing, platform immutability or measured efficiency.

See [the feature contract](../work-items/20261028-v0-12-publication/feature-contract.md)
and [the exact publication decision](../decisions/0024-v0-12-publication-and-separate-closeout.md).
Independent source QA, merged-source release gates and public acceptance are
separate evidence obligations.
