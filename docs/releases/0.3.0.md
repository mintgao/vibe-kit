## What changed

0.3.0 closes two loops: projects can turn evidence-backed Vibe Kit friction into sanitized local improvement candidates, and maintainers can build one version into a deterministic offline payload plus a bootstrap-only Codex Plugin. Both channels install the same repository-pinned runtime.

## Build and verify

```bash
./bin/vibe doctor .
python3 -m unittest discover -s tests -v
./bin/vibe package --status prerelease
./bin/vibe validate-release dist/vibe-kit-0.3.0
```

`package` refuses a non-empty output directory. Prerelease packaging also refuses an uncommitted or dirty source. The release ZIP, Plugin ZIP, expanded local marketplace, `release-manifest.json`, `SHA256SUMS`, and deterministic distribution bundle are produced from one source tree. Repeating the build with unchanged input must produce identical ZIP digests.

## Installation paths

### Offline or GitHub Release payload

1. Download and extract `vibe-kit-distribution-0.3.0.zip`; it contains the complete release directory.
2. Run `validate-release` from a trusted Vibe Kit CLI before installing.
3. Extract the inner `vibe-kit-0.3.0.zip` to a separate payload directory.
4. Run `bin/vibe plan init <project>` for a new project or `plan adopt <project>` for an existing project.
5. Review the plan, run the matching write command, then use the installed project's `bin/vibe doctor`.

### Codex Plugin

Add the generated `marketplace/` root as a local marketplace, install `vibe-kit@personal`, and start a new Codex task. `$vibe-bootstrap` plans and performs init/adopt; `$vibe-maintain` plans upgrades and runs diagnostics. The Plugin never replaces repository runtime Skills and does not contain MCP, hooks, apps, or a network updater.

### Share an already adopted project

Commit `AGENTS.md`, `bin/vibe`, `.vibe/core/`, `.vibe/manifest.json`, `.vibe/version`, `.codex/agents/`, `.agents/skills/`, project rules, and durable context. A collaborator only needs the cloned repository and Python 3.9+ to run `./bin/vibe doctor`; the original maintainer's Plugin is not required.

## Upgrade and rollback

Use the selected newer payload's CLI to run `plan upgrade <project>`, then `upgrade`. Three-way conflicts stop before managed files or installation state change and place incoming candidates under `.vibe/conflicts/` for manual comparison. Project rollback uses Git revert or a controlled upgrade from an older verified payload; do not edit version files directly.

## Prerelease boundaries

- Repository: Public `mintgao/vibe-kit`, MIT licensed.
- Release: annotated `v0.3.0` tag and GitHub Pre-release; not a stable channel pointer.
- Feedback destination: `mintgao/vibe-kit`, still exact-payload consent-bound and never automatic.
- Build in Linux CI, download the published distribution bundle, rerun validation/smoke, and decide signing/provenance before stable promotion.
- Public Codex Plugin Directory, npm, PyPI, Homebrew and non-Codex adapters remain out of scope.

The GitHub prerelease proves the authenticated publisher, commit/tag, deterministic artifact content and documented SHA-256. It does not claim Linux execution, signed provenance or stable compatibility.
