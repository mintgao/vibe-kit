# Vibe Kit v0.10.0

This is the selected non-draft GitHub Pre-release candidate. Public completion is recorded only after live verification.

## Changes

- Readiness accepts both numbered and date-named Accepted decision records and reads a record's heading and status from its own grammar. `work-item` no longer double-prefixes a dated slug, and `feedback submit --confirm` documents the required fresh token form.
- The verification contract is closed: a project may declare check order through `checks.requires`, a failing check keeps a full recoverable output artifact beside the bounded receipt tail, an unmet declared toolchain records an `environment-limited` verdict with the observed toolchain, and the operating model sanctions a constrained-QA path for hosts whose subagent budget is smaller than the lane.
- The takeover object is published as a contract: `AGENT_INSTALL.md` documents its closed field sets, custody transitions, evidence placement and sequence rules, takeover-capable commands write byte-stable `--receipt` artifacts, the minimal manual-transfer payload is validated, and a healthy existing installation is admitted through an `existing-install-admission` receipt that claims no new transaction in that directory.
- Host adapters: the Agent-install contract declares a per-host registry (protocol, capability claims, conformance label and payload paths), `init`/`adopt`/`upgrade` accept a `--host` selection, an installed copy records its selection in the manifest and the activation identity, and Hermes is published first-class with a specialist-role mapping. Codex stays the verified integration; Hermes is recorded `supported-unverified`.
- Exact publication schema 4 binds v0.10.0 to six operations and five assets, with a separate closeout schema 3 that permits only #8–#13 after public verification. Historical v0.7/v0.8/v0.9 profiles retain their boundaries.

## Compatibility and limits

Kit 0.10.0 uses core/Codex protocol 7 and Hermes adapter protocol 1 and requires Python 3.9+. The maintenance bridge admits installed versions from 0.2.0 up to, but not including, 0.10.0, and installed Agent-install protocols 0–3 stay upgradeable; the Agent-install contract itself is schema/protocol 4. Healthy v0.3/v0.5/v0.6/v0.7/v0.8/v0.9 predecessor smokes remain required for public verification. Source doctor proves installation integrity, not runtime activation.

The CLI does not lock filesystem writes, authenticate human review or host consent, perform network writes, publish over the network, or provide publisher signatures. The Hermes conformance label stays `supported-unverified` until its five-stage record is complete, and no live same-task reload or automatic successor handoff is claimed.

The five public assets are SHA256SUMS, release-manifest.json, vibe-kit-0.10.0.zip, vibe-kit-distribution-0.10.0.zip and vibe-kit-plugin-0.10.0.zip. No stable promotion or Plugin Directory publication is included.
