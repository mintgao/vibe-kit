# Vibe Kit 0.7.0 Pre-release

Vibe Kit 0.7.0 closes the five accepted resilience, trust and publication issues.

## Highlights

- Upgrade is now a scoped recoverable transaction. Handled failures either prove
  rollback, preserve integrity-checked recovery evidence, or fail closed without
  overwriting an unclassifiable value.
- Final installation entries use capability-probed, fd-relative lossless
  primitives: hard-link publication for absent leaves, atomic exchange for
  existing leaves, and adjacent prepared no-replace directory units for a first
  missing managed parent. Unsupported platforms or filesystems block without an
  ordinary-rename fallback.
- `recover-upgrade` finalizes a committed target or restores exact predecessor
  preimages without Git, network access or the original target payload.
- Only the audited v0.2 fixture and exact official v0.3/v0.4 identities can receive
  a create-only persisted `pending` onboarding bridge. Existing valid onboarding
  is byte-preserved; missing v0.5/v0.6 onboarding is treated as state loss.
- Trust text now separates exact source selection, verified content identity and
  observed platform-enforced immutability.
- A first-class repository release Skill produces canonical offline intents and
  validates host receipts for exact main/tag/Pre-release/five-asset publication,
  public download smoke and separately authorized issue #1–#5 closeout.

## Contract versions

- Core/Codex protocol: 5
- Agent-install schema/protocol: 3
- CLI result/takeover/maintenance bridge/compatibility registry/release manifest: 2
- Transaction journal/commit marker/publication intent/receipt/closeout intent: 1
- Installed manifest/onboarding: 1
- Feedback protocol: 2

The CLI remains Python 3.9+ standard-library-only and offline-capable. GitHub
credentials, network operations and platform immutability observations remain in
the Agent/host boundary. This is a Pre-release, not a Stable promotion.
