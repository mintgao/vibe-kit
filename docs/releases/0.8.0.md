# Vibe Kit 0.8.0 Pre-release

Vibe Kit 0.8.0 makes workflow execution risk-adaptive and artifact-first while
preserving the existing readiness, independent review, single-writer, recovery,
privacy, and verification boundaries.

## Highlights

- Risk-first S/M/L routing no longer treats tightly coupled file count as a size
  trigger; user-flow/shared-contract work remains at least M and cross-system or
  high-risk work remains L.
- Specialist handoffs are bounded to authoritative artifacts and disclose when
  the host cannot prove transport-level context isolation.
- RD owns focused development checks and independent QA owns one complete
  default verification for an unchanged normal M/L candidate.
- Source, install, package and Plugin identities advance to 0.8.0 with core and
  Codex protocol 6 while carrying forward upgrade recovery and takeover safety.
- The closed v0.8 publication profile uses intent/receipt schema 2, exactly five
  public assets, six no-Issue operations, per-object attempt ledgers, two-phase
  QA evidence, actual CPython 3.9 gates, and two byte-identical clean builds.

## Publication and compatibility

This release is a non-draft GitHub Pre-release. The exact public asset set is
`SHA256SUMS`, `release-manifest.json`, `vibe-kit-0.8.0.zip`,
`vibe-kit-distribution-0.8.0.zip`, and `vibe-kit-plugin-0.8.0.zip`.

Historical v0.7 schema-1 publication and Issue #1–#5 closeout remain exact. The
v0.8 operation set contains no Issue action or closeout authorization. The CLI
remains Python 3.9+ standard-library-only and performs packaging and publication
validation offline; GitHub authentication and network activity remain host-owned.

An exact tag or Release URL selects a specific published version but does not by
itself prove platform immutability or publisher provenance. Verify transferred
bytes against their SHA-256 and nested release validation results.
