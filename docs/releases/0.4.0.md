## What changed

0.4.0 turns the local-first feedback mechanism into a visible maintenance loop. New and missing project configuration defaults to `feedback.mode: ask`: after an M/L task is complete, a qualifying new or materially changed Vibe Kit gap is sanitized, deduplicated and presented once as an exact local review. The user can authorize that one payload with an adjacent, unambiguous reply; no configuration or mode grants blanket external-write consent.

The CLI adds mode-aware `feedback close`, read-only `feedback mode`, sanitized `feedback revise`, attention state schema 2, legacy-backlog suppression and semantic security-sensitive public-submission blocking. Existing manual draft/review/check/submit/dismiss workflows remain compatible.

```bash
./bin/vibe package --status prerelease
./bin/vibe validate-release dist/vibe-kit-0.4.0
```

The published bundle is built from a clean commit with an explicit `--status prerelease` invocation. The default unpublished package mode remains available for local release-candidate work.

## Upgrade behavior

Use the selected 0.4.0 payload or Plugin to run `plan upgrade` and then `upgrade`. Project-owned `.vibe/project.yaml` is preserved: explicit `local` or `off` remains unchanged, while a missing mode resolves safely to `ask`. Historical feedback state is normalized lazily as legacy and is not bulk-presented; only later material evidence can resurface it.

Rollback is immediate at the policy layer by selecting `local` or `off`. Source rollback uses Git revert or a controlled verified older payload; never edit installed version or manifest hashes to bypass diagnostics.

## Release boundaries

- 0.4.0 is a GitHub Pre-release, not a stable release or public Codex Plugin Directory version.
- No telemetry, background networking, automatic Issue submission or long-lived blanket consent was added.
- Security-sensitive reports remain local until an approved private disclosure path exists.
- The bootstrap Plugin remains an offline installation/maintenance channel; repository-pinned runtime files remain authoritative.
