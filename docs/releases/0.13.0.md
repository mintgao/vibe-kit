# Vibe Kit 0.13.0 — unpublished Pre-release candidate

This candidate targets a non-draft GitHub Pre-release. Source implementation and
offline validation do not establish publication, final product acceptance or
active host rules. The published installation baseline remains v0.12.0 until
0.13.0 has completed its required public verification.

## Changes

- Runnable Python/Node extension-contract templates call the production receipt
  validator through real discovery/package dispatchers. Complete and partial
  receipts, field/set/order/summary counterexamples, loaded origins and arguments,
  output semantics, integrity and doctor lifecycle are tested separately.
- Optional `check-upgrade-compatibility` reads a project-owned payload allowlist
  and the selected target identity without hooks, network calls, writes or
  upgrades. Missing or disabled declarations add no upgrade requirement. Changed,
  unsafe, malformed or unavailable input stays distinct from a rejected identity.
- Protocol-5 guidance separates known pre-QA maintenance from a real failed check.
  Actual target activation, accepted technical decisions, scoped maintenance,
  preserved guards and final independent QA remain required before business work.
- Bounded evidence and maintenance guidance keeps original run/candidate facts,
  current applicability, owner and one next action separate. Read back uncertain
  operations before continuing; unknown or divergent transactions stop automatic
  repair. Existing recovery cleans a committed target or restores a proved
  predecessor; it is not an arbitrary downgrade API.
- Exact publication intent/receipt schema 8 binds only 0.13.0 to five assets,
  six operations and twenty ordered public smokes. It requires the final product
  matrix, a reviewed public PR, actual merged-source QA and two clean builds.
  Issue policy is `none`; no issue-closeout or project-upgrade stage is added.

## Compatibility and limits

The CLI remains offline-capable, Python 3.9+ and standard-library-only. Node is
needed to execute the Node examples; it is not a CLI dependency. Agent-install
schema/protocol is 4/5, core/Codex remains 7/7 and Hermes remains 1. Existing
verification, inspection and transaction schemas are unchanged. Historical
publication 1–7 and closeout 1–5 retain their exact meanings; schema 7 stays
exclusive to 0.12.0 and closeout 5 retains that historical parent.

Payload identity equality does not prove semantic or API compatibility.
Compatibility source authentication stays `not-attested`. Historical inspection
retains origin `not-attested`, applicability `unproven` and liveness `not-assessed`.
Controlled fixtures, static tests, metadata and hashes cannot establish genuine
host activation, live-model compliance, measured efficiency, publisher signing
or platform immutability. A missing live criterion remains Blocked.

The Plugin remains a bundled bootstrap/maintenance entry with no task-creation
or reload API. Its compatibility preflight calls the authenticated bundled CLI
directly; the old wrapper does not dispatch that command. Runtime maintenance
and host evidence remain separate from read-only observation.
